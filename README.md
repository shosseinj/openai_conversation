# Persian voice conversation

A browser microphone app for Persian voice conversation with OpenAI **GPT-Live 1**.
The default startup is **OpenAI only**: it does not import or load Whisper,
DeepFilterNet, Silero VAD, or speaker verification, and needs no NVIDIA GPU.
The existing Local pipeline remains available as an explicit option on its
existing Ubuntu installation.

## Start automatically

You need Python **3.10 or newer** (3.12 recommended), an internet connection,
and an OpenAI project API key with access to `gpt-live-1`. For conversation
reasoning, the app also uses Responses delegation with `gpt-6-luna` by default.
A current Chrome, Edge, or Firefox browser with microphone permission is needed.

### Windows

Open this project folder and **double-click `run.bat`**.
If Python is not installed, install it from https://www.python.org/downloads/
with the Python launcher/PATH option, then run the file again.

PowerShell is also supported:

```powershell
.\run.ps1
```

If Windows blocks the PowerShell script, use `run.bat`, or run it for this
invocation with `powershell -NoProfile -ExecutionPolicy Bypass -File .\run.ps1`.

### Ubuntu / Linux

On Sharif:

```bash
cd /home/sharif/Music/whisper
./run.sh
```

For a fresh checkout, install the Python bootstrap tools once if absent:

```bash
sudo apt update
sudo apt install python3 python3-venv python3-pip
cd /path/to/this/project
chmod +x run.sh
./run.sh
```

PowerShell 7 on Linux can also run `pwsh -File ./run.ps1`.
The launchers run the server on the machine where you execute them; they do
not automatically SSH to Sharif. To start Sharif from another computer:

```bash
ssh sharif@192.168.100.96
cd /home/sharif/Music/whisper
./run.sh --no-browser
```

### What the runner does

1. Uses the project's existing `.venv`. Only a fresh checkout without `.venv`
   creates one; an existing environment is never deleted or replaced. `run.sh`
   activates it automatically; other launchers use its Python and environment
   directly. You do not need to activate it manually.
2. Installs/checks the packages in `requirement.txt` → `requirements.txt`.
   No Local models or GPU packages are installed by default.
3. Reuses `certs/server.key` and `certs/server.crt`, or generates development
   HTTPS certificates if both are missing.
4. Stops processes listening on the selected TCP port. It first terminates
   them, then force-kills them if needed. This applies to **any listener** on
   that port. If ownership/permissions prevent cleanup, startup reports an error.
5. Starts the OpenAI-only app on **`0.0.0.0:8500`** and opens the frontend after
   the server is ready. Keep its terminal open; **Ctrl+C** stops the app.

Open `https://localhost:8500/` on the server, or
`https://192.168.100.96:8500/` from another device on Sharif's network.
`0.0.0.0` is the bind address; use the server's actual IP in your browser.

## First browser setup and conversation

The runner prepares HTTPS automatically, but browser certificate trust and
microphone permission are one-time browser/OS steps.

If the browser does not trust the certificate, import **`certs/ca.crt`** as a
trusted certificate authority on the device opening the page. On Windows,
from the project folder:

```powershell
certutil -user -addstore Root .\certs\ca.crt
```

On Ubuntu you can install the local CA into the system trust store:

```bash
sudo cp certs/ca.crt /usr/local/share/ca-certificates/persian-voice.crt
sudo update-ca-certificates
```

Restart the browser. If it uses its own certificate store, import the same CA
through browser certificate settings. Another device must trust this server's
CA, rather than a certificate generated by its own checkout. The public CA can
be downloaded from `/certificate`; private key files stay on the server.

Then:

1. Select **OpenAI — GPT-Live 1** (the default; Local is disabled).
2. Paste the API key into the masked **OpenAI API key** field.
3. Click **شروع مکالمه** and allow microphone access.
4. Speak Persian. Assistant audio and both speakers' transcripts stream into
   the page. You can interrupt a response by speaking.
5. Click **پایان مکالمه** to close the session. Stop before switching engines.

The key is sent to this application's backend over HTTPS for that session
creation request, cleared from the field, and not saved to disk, browser
storage, or conversation history. Enter it again for the next conversation.
Alternatively, set `OPENAI_API_KEY` in the server environment; the field is
then optional. The server never sends its environment key to the browser.
`.env` files are ignored by Git, but are **not automatically loaded**.

Within a Live session, OpenAI manages conversation context. After stopping and
restarting on the same page, the app sends a bounded recent transcript history.
Reloading or clearing the page removes that in-memory history.

## Runner options

```bash
# Skip dependency installation after the first successful setup:
./run.sh --skip-install

# Server/headless use:
./run.sh --no-browser

# Different port; its existing listener will also be stopped:
./run.sh --port 8501
```

```powershell
.\run.ps1 -SkipInstall -NoBrowser -Port 8501
```

Windows batch accepts the Python-style options too:
`run.bat --no-browser --port 8501`.
You can always use `python run.py` with the same options as `run.sh`.

For manual startup with the existing environment:

```bash
source .venv/bin/activate
python -m pip install -r requirement.txt
python app.py
```

`app.py` also prepares missing certificates and frees its selected port.
It accepts `--host`, `--port`, `--open-browser`, and `--enable-local`.

## Optional existing Local engine

Local is off by default. Its existing pipeline is preserved:

`Microphone → DeepFilterNet → Silero VAD → ECAPA speaker verification → Whisper Persian V4`

To enable it on the existing configured Ubuntu project:

```bash
./run.sh --enable-local
# Or, inside the existing environment:
python app.py --enable-local
```

PowerShell: `.\run.ps1 -EnableLocal`.
The frontend starts on OpenAI; Local becomes selectable. Stop the current
session before selecting Local. Local makes no OpenAI calls.

Local assets and dependencies are intentionally excluded from the automatic
OpenAI setup. A separate Local installation needs matching CUDA-enabled
PyTorch/torchaudio, the packages in `requirements-local.txt`, FFmpeg, PortAudio
for terminal microphone capture, the existing Linux DeepFilterNet native
library at `deepfilter/libdeep_filter_ladspa.so`, the Whisper model at `model/`,
and the SpeechBrain ECAPA model. These assets already exist on Sharif.
Use https://pytorch.org/get-started/locally/ to choose a matching torch/torchaudio
build before installing optional Local requirements. The Linux DeepFilterNet
library is not a Windows Local backend.

Whisper: `nezamisafa/whisper-persian-v4`.
Speaker verification: `speechbrain/spkrec-ecapa-voxceleb`.
Enroll using the frontend microphone button or
`python enroll_speaker.py patient.wav` with 15–30 seconds of clean target speech.
See [README-speaker.md](README-speaker.md) for Local usage.

## Configuration

| Setting | Default | Purpose |
| --- | --- | --- |
| `--host` / PowerShell `-BindAddress` | `0.0.0.0` | Server bind address |
| `--port` / PowerShell `-Port` | `8500` | HTTPS port, automatically freed |
| `OPENAI_API_KEY` | Unset | Optional backend key; frontend entry also works |
| `OPENAI_LIVE_BACKEND_MODEL` | `gpt-6-luna` | Responses delegation model |
| `ENABLE_LOCAL_STT` | `0` | Direct `app.py`: set `1` to enable Local |
| `HTTPS_NAMES` | Auto-detected host/IPs | Comma-separated additional names for newly generated certificates |
| `TARGET_SPEAKER` | `target_speaker.pt` | Optional Local enrollment profile |
| `SPEAKER_THRESHOLD` | `0.5` | Default Local speaker similarity threshold |

Runners explicitly disable Local unless `--enable-local` / `-EnableLocal` is
passed, even if the parent shell previously enabled it.
Existing certificates are reused without alteration. For a changed hostname/IP,
set `HTTPS_NAMES` and prepare a new certificate pair deliberately, or install a
matching trusted server certificate in `certs/`. Generated server certificates
last one year; generated CA certificates last ten years.

## Development and tests

Default/OpenAI tests need only the default requirements, no key or Local models:

```bash
.venv/bin/python -m unittest test_openai_voice test_server_startup -v
```

Windows: `.venv\Scripts\python.exe -m unittest test_openai_voice test_server_startup -v`.
These tests cover per-request key handling, sanitized errors, no Local imports,
port cleanup, and HTTPS generation/reuse. They mock the upstream OpenAI request;
an authenticated audio conversation still requires your real API key.

Full Local regression tests on the existing Sharif environment:

```bash
ENABLE_LOCAL_STT=1 .venv/bin/python -m unittest discover -v
```

The Local diagnostic tests also require `persian_sample.wav`, which is a local
ignored audio fixture. It is not included in a fresh Git checkout.

## Troubleshooting

- **Missing Python / venv:** install Python 3.12; on Ubuntu install
  `python3-venv`. A `.venv` copied from another OS is not portable; use a separate
  checkout for that OS. The runner does not replace an existing environment.
- **Package installation fails:** verify network access and retry. Use
  `--skip-install` only after dependencies are already installed.
- **Microphone unavailable:** trust the server CA, use its HTTPS URL, and allow
  microphone access in the browser.
- **Cannot reach the LAN URL:** verify the server is running on `0.0.0.0`, the IP
  is current, and the network/firewall allows your chosen TCP port.
- **Port cannot be freed:** its process may belong to another user. Resolve the
  ownership/permissions, or choose another port.
- **Rejected key / model unavailable / quota:** use a project key with access to
  GPT-Live and the configured backend model, and verify your API quota.
- **Local is unavailable:** this is intentional for default startup. Use the
  explicit enable flag only after Local dependencies and assets are ready.

## Privacy and repository contents

Environment files, certificates/private keys, `.venv`, recordings, enrolled
speaker embeddings, downloaded models and diagnostic outputs are ignored by Git.
Keep secrets out of source files. OpenAI mode sends audio and supplied transcript
context to OpenAI. Local mode processes audio through the existing local models.

This is a development app for your own machine/trusted LAN. It has no application
login or user isolation and is not configured for public internet deployment.

Protocol reference: [official GPT-Live WebRTC documentation](https://developers.openai.com/api/docs/guides/voice-webrtc).
